# 模块设计与演示说明

## 模块与职责

| 模块 | 主要职责 | 关键接口 |
| --- | --- | --- |
| blocks | 密钥、签名交易、Merkle、封装与 UTXO 验证 | make_chain / Ledger.accept |
| network | TCP 监听、控制帧、HELLO、心跳、共享队列、下载 | Network / discover / maintain / SyncClient |
| storage | 公开夹具导出和读取，读取后独立验证 | save_chain / load_chain |
| demo | 串起 101 节点的单次实验并收集页面数据 | demonstration |
| app | 参数输入、状态展示、原始数据导出 | Streamlit 页面 |
| run_experiments | 固定设计、随机顺序、重复测量、CSV 和环境记录 | 命令行 |
| analyze | 数据完整性审计、均值与样本标准差、图表 | 命令行 |
| tests | 验证密码学、输入边界、状态与真实网络恢复 | unittest |

## 状态和边界

新节点：初始高度 0 → HELLO 邻居传播 → 主动探测活跃节点 → 获取头部清单 → 与可信目标检查点对照 → 下载 → 按高度验签及校验 → 更新可服务高度。GET 不能索取尚未验证的高度。

下载任务：待处理 → 请求提供者 → 接收响应 → 接收分块 → 完整哈希校验 → 等待按序验证。连接中断、超时和 BUSY 进入有界退避；优化方案保留前缀并切换节点；内容校验失败清空前缀。30 次尝试仍失败则显式报错。

活跃表：未知 → 邻居广告候选 → 成功探测后活跃 → 一轮失败仍保留 → 连续两轮失败或 TTL 超时后失活 → 成功探测后重置失败次数。网页每次实验显式执行两轮维护；命令行或部署服务可在计时器中周期调用 maintain。演示页面没有一直运行的后台 101 节点集群，单次实验结束后关闭所有监听。

公平性控制：先生成不可变区块，复用公开夹具；同一机器、拓扑、4 个提供者、参数与重复次数；每次清空下载及故障状态；场景和策略顺序打乱。串行基线具有换源与重试，优化的是有界并行、轮换、冷却与续传的组合。
