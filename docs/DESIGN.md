# 协议及模块设计

## 1. 对照教材

依据已上传2026版《第一章》给出身份拆分、抽查、商户随机挑战及存款识别；第16节（印刷页15）要求三角色、状态隔离、安全随机量和原子更新。本实现保留这些逻辑，用明确的单现金 N−1 抽查变体代替讲义约一半抽查的批量方案。

## 2. 数学结构

注册时分配随机256位身份 U，银行保存账户到 U 的注册映射。U 不是用户名哈希，避免低熵枚举。对每个位置 i，钱包独立生成256位 a_i，令 b_i = a_i XOR U。对两分支分别生成独立256位盐，承诺为：

`H([domain, serial, i, side, share, salt])`。

一枚现金消息包含版本、密钥指纹、固定面额10、256位序列号、t和t对承诺。所有字段被规范JSON和域分离全域哈希代表值 m 绑定。RSA modulus 为2048位；从可逆群随机选择独立 r，提交 B=m*r^e mod n。银行返回 S=B^d mod n；钱包计算 s=S*r^−1 mod n，自检 s^e=m。代表值使用SHAKE256拒绝采样到 Z*_n，避免把可选择消息直接当作裸RSA整数。

付款人先生成 N 套独立候选并提交全部盲化值。银行保存不可修改的提交向量，再随机选一枚不打开，其余 N−1 枚须打开消息、两边分片、盐和r。银行验证承诺、每对XOR、身份归属和盲化一致性；通过后仅盲签未打开值。保存的发行表不含未打开消息、序列号或钱包ID，开封材料只在方法调用中验证，不持久化。

商户验签后以 secrets.randbits 为每位独立选择挑战。付款人只公开各位置被选的一边（share,salt）。商户验证承诺后先离线接受；银行尚未参与，因此两商户可能均接受同一现金。

存款提交完整现金、商户、支付会话号、挑战和响应。银行重新完整验证。首次序列号清算入账。重复序列号对应同一现金时，比较两份已验证凭证；只要一位不同，两个share XOR得出 U，再通过**注册身份映射**找账户。这不是通过发行序列号找付款人。相同挑战只能检测重复，不能恢复 U。不同位置恢复不一致则拒绝归因，提示候选可能作弊。

## 3. 状态与事务

| 区域 | 正常状态 | 异常 / 重试 |
|---|---|---|
| 银行取款 | CHALLENGED → SIGNED | CHALLENGED → CANCELLED / REJECTED |
| 钱包 | PREPARED → CHALLENGED → READY → SPENT | 取消进入CANCELLED；签发后重试返回原盲签 |
| 商户 | CHALLENGED → ACCEPTED → DEPOSITED | 重复存款进入DUPLICATE；未过验证保持原状态 |

提交时一次原子事务扣10（等价预留金额）。抽查失败或主动取消，终止请求并只退一次。SIGNED不允许取消，重复签发仅返回同一结果，不再扣款。余额 CHECK 非负；账户密码验证、角色、active与余额均在写事务内检查。重复提交过的盲化值拒绝，包含取消和失败记录，避免再次随机抽查同一候选。

数据库采用 BEGIN IMMEDIATE、忙等待和唯一键 deposits(serial)。完整凭证验证在去重前完成；取得写锁后读取旧凭证、插入首存并增加余额，或保存重复证据，最后一起提交。并发请求串行化，失败回滚；不存在先查后写的无锁空窗。完全相同凭证重试返回REPLAY且不再入账。相同挑战的不同会话记为DUPLICATE_SAME_CHALLENGE，不能据此断言已识别付款人。重复证据UNIQUE防同一记录无限增长。

钱包正常拒绝同一现金回应新会话。仅明确开启攻击演示允许重复响应，用于模拟复制数字文件。已回应同一会话可幂等重发。商户挑战固定持久化，不接受付款人替换；验收只接受本商户生成的请求。会话号由secrets独立生成。

崩溃边界：银行签发成功而钱包未去盲可重试同请求。提交成功而钱包尚未记录挑战的极短跨库窗口，银行页可看到预扣请求；付款人可在原PREPARED条目再次点击提交，界面按原盲化向量找回待抽查请求，不重复扣款；恢复后可继续或取消（冻结账户需先解冻）。没有跨三个SQLite文件的分布式事务，这是本机教学限制，不应承诺故障下完全自动恢复。取消和退回银行金额在同一bank.db事务内完成。

## 4. 概率及随机数

- 单个坏候选事先固定位置，随机留下它的概率1/N。若至少两个坏候选，开N−1必遇坏候选。此变体没有随N指数衰减的安全性；默认N16仅演示，N64也只有1/64单轮逃逸界。重复尝试会增加累计成功机会，不能把每次重新生成后的1/N理解为系统终生界。
- 两个诚实独立商户挑战t位全相同概率2^−t，至少一位互补概率1−2^−t。t32时前者约2.3283e−10。独立性和诚实商户是前提；商户串通、可预测或故意相同挑战不满足此界。
- a_i、盐、序列号、r、银行抽查、会话号和挑战位均来自secrets。RSA密钥由cryptography系统随机源生成。禁止random、固定种子及跨位置/跨现金重用。复用掩码可能关联现金甚至组合泄露身份；复用r降低盲化独立性；复用盐或序列号破坏隐私和唯一性。
- 输入限定候选2–64、t8–128、固定面额、规范十六进制长度、RSA标量群成员、精确字段集合、向量长度、挑战二元整数。布尔值不能冒充整数。

## 5. 匿名性与安全边界

单份凭证只给出每对的一边，独立掩码及未公开高熵盐隐藏另一边。银行没有最终现金的发行映射；不同支付同一现金本身可链接，这是识别重复的基础。实际时间、金额、t配置等元数据会缩小匿名集，独特配置尤其易关联。

此教学实现并非完整CFN协议，也非RFC9474。没有对恶意参与者的完整不可伪造、盲性、抗诬陷和one-more-RSA证明；抽查失败概率有限，攻击者可在未开封候选构造错误身份并逃逸，因此恢复身份在教学威胁模型下才可归因，不能当法律证据。付款人若主动回应恶意商户的第二个挑战，也可能在未获得第二次商品时暴露身份。默认钱包防重答降低诚实用户风险，但复制钱包会绕过。

私钥d、钱包两边分片和盐、r、账户密码、身份U和完整响应均为敏感数据。页面不展示私钥或导出钱包秘密；只可导出公共现金与已公开支付凭证。密码采用PBKDF2-HMAC-SHA256/200000和独立盐，不以明文保存；没有登录限速、服务器鉴权、HTTPS、数据库加密、HSM、常数时间RSA及前向安全。私钥和钱包秘密明文存本机数据库，不对本机管理员保密；SQLite旧页也不保证安全删除。请仅用虚拟身份、实验余额。

收款人纯协议类仅接受公钥快照，不访问银行。Streamlit是同机角色观察台，其账户选择、公共现金传递和密码登录属于模拟器编排，不代表三个独立安全客户端。可通过导出现金手工传递，也可把Merchant与公钥放到独立进程演示，但项目没有实现网络分布式部署。

固定面额不可找零，不支持转让、拆分、撤销、密钥轮换或到期。密钥只允许首次生成，避免覆盖已有钱包的发行根。只有付款人注册获100，商户注册获0；
