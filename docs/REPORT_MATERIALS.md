一、实验内容与要求
本实验依据《第一章》第16节，使用 Python、Streamlit 与 SQLite 实现银行、付款人和收款人三个逻辑角色，完成初始化、取款、离线支付及存款。系统目标是在正常支付时隐藏付款人身份，在同一电子现金被重复支付且挑战不同的情况下，由银行根据互补响应恢复身份。

银行支持密钥生成、候选抽查、RSA教学盲签、存款验证、双花记录与身份恢复；付款人支持候选生成、盲化、抽查应答、去盲和挑战响应；收款人支持银行验签、独立随机挑战、响应验证与存款提交。同时实现余额控制、状态约束、非法输入校验和并发清算。

2 盲签与身份拆分的实现

银行注册时为账户分配随机256位身份U。每个位置i独立生成掩码aᵢ，令bᵢ＝aᵢ XOR U，两分支分别使用独立随机盐生成承诺。承诺的输入同时绑定域标识、现金序列号、位置和分支，防止将响应移动到其他现金或位置。

Cᵢ,₀ = H(domain, serial, i, 0, aᵢ, saltᵢ,₀)
Cᵢ,₁ = H(domain, serial, i, 1, bᵢ, saltᵢ,₁)

现金消息M包含版本、密钥指纹、面额、随机序列号、挑战位数和全部承诺。规范JSON经域分离SHAKE256拒绝采样，得到RSA可逆群中的代表值m。钱包随机选择与n互素的r，按以下过程盲化、盲签和去盲。

B = m · rᵉ mod n     S = Bᵈ mod n
s = S · r⁻¹ mod n     验证 sᵉ mod n = m

正确性来自ed在RSA可逆群上的指数关系：S＝mᵈ·r，因此去除r后得到对m的签名。r必须可逆；代码验证RSA标量的范围和最大公约数，不允许零值、非规范编码或非群成员。

3 随机抽查与商户挑战

本实现采用“生成N枚、打开N−1枚、只签剩余1枚”的单现金变体。银行先接收不可修改的盲化向量，再随机选择保留索引。开封时验证每个承诺、两边分片的XOR是否属于取款账户，以及公布的r能否重建原盲化值。开封材料不持久化，未打开现金的序列号不进入发行表。

商户验签后独立生成t个挑战位；付款人只公开对应分支的分片和盐。商户逐位检查承诺，单次凭证不包含完整身份。若同一现金的两份有效凭证在某位置挑战相反，银行即可将互补分片XOR，恢复U。

4 状态控制与数据库事务

参与方	主状态路径	异常处理
银行	CHALLENGED → SIGNED	失败或取消进入终止态并退回预扣款
付款人	PREPARED → CHALLENGED → READY → SPENT	正常拒绝重复响应；攻击演示须明确开启
收款人	CHALLENGED → ACCEPTED → DEPOSITED	重复清算进入DUPLICATE

提交取款时在同一事务中校验账户、角色、启用状态和余额，并预扣10个实验单位。抽查失败或主动取消只退回一次；签发完成后不可取消。重复签发返回原结果，不重复扣款。历史提交过的盲化值禁止重用，避免对同一候选反复抽查。

bank.db中的issuance表保存账户、盲化向量、抽查索引和发行状态；deposits表保存首次存入的现金及支付凭证；evidence表保存重复凭证和恢复结果。付款人秘密位于独立钱包数据库，商户挑战与验收状态位于独立商户数据库。发行记录和存款记录没有最终序列号关联字段。

银行先验证完整凭证，再以BEGIN IMMEDIATE取得写锁，在同一事务内查询首次存款、插入记录并增加商户余额，或保存重复证据。deposits(serial)主键提供唯一约束；任意异常回滚。完全相同凭证重试返回REPLAY，不再次入账。仅有序列号查重只能完成清算去重，身份恢复仍依赖离线挑战证据。

5 随机数与输入校验

掩码、盐、序列号、盲化因子、银行抽查、会话号和挑战位均使用secrets；RSA密钥由cryptography生成。复用掩码可能关联不同现金或暴露身份，复用r削弱盲化独立性，复用序列号会使不同现金被误判重复，因此每次独立采样且禁止重复提交。

输入校验包括固定面额10、候选数2至64、挑战位数8至128、十六进制长度、精确字段集合、向量长度及二元整数挑战。密码使用独立盐与PBKDF2-HMAC-SHA256进行200000次迭代保存；冻结账户不能取款或存款，余额由数据库约束保持非负。

跨银行、钱包和商户三个数据库没有分布式事务。银行已签发但钱包未完成去盲时可重试原请求；提交后短暂中断可按原盲化向量找回待抽查状态，但不能据此承诺任意故障都能自动恢复。

挑战相同的概率边界

诚实商户独立选择t位二元挑战时，全部相同概率为2⁻ᵗ，至少一位不同的概率为1−2⁻ᵗ。t＝32时前者约为2.3283×10⁻¹⁰；这是理论概率，不是本次少量试验估计的频率。边界测试在测试环境注入相同挑战，返回“同挑战重复存款”状态，身份字段为空，第二次仍不入账。

五、实验总结
本实验完成了初始化、取款、离线支付和银行清算的完整教学流程。实验结果表明，签名保证发行真实性，盲化降低银行在取款时获知最终现金消息的能力，随机挑战与身份拆分支持双花后的条件身份恢复；SQLite事务与唯一约束则保证重复现金不会被并发兑付两次。上述机制各自承担不同职责，不能用单一“验签成功”代替完整的安全判断。
实现中需要特别处理“正常重复请求”与“重复支付”的区别：同一签发请求重试应返回原结果，同一存款凭证重试不应重复入账，新的支付会话则必须由商户独立生成挑战。钱包默认阻止二次响应，只有显式攻击演示才绕过该限制，从而既能演示可复制现金带来的双花，又避免正常操作误泄露互补分片。
教学简化与安全边界
本项目采用固定面额10，不支持找零、拆分、转让、密钥轮换或到期处理。RSA-FDH式盲签仅用于解释数学结构，不等同于RFC 9474的RSA-PSS盲签，也未给出完整不可伪造、盲性、one-more-RSA或抗诬陷证明。抽查有非零作弊逃逸概率；恶意候选若逃过抽查，身份恢复不能直接等同于现实中的可靠追责。
单次匿名性依赖独立随机掩码和高熵盐；两次身份恢复的概率界依赖诚实、独立的商户挑战。恶意商户若诱导同一现金回应两次不同挑战，也可能导致身份暴露。默认钱包防重复响应能够降低风险，但复制钱包可绕过本地状态控制。
私钥、盲化因子、完整分片、盐、身份和支付凭证均应按敏感数据管理。项目没有日志脱敏体系、数据库加密、登录限速、硬件密钥托管及常数时间RSA；钱包和银行秘密以明文存于本机数据库。因此不对本机管理员承诺匿名，也不用于真实资金。进一步改进应采用有安全证明的协议、严格客户端隔离及更完善的密钥与故障恢复机制。
